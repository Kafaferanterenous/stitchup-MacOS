# Stitchup — Stage 0: Sanitized Fixture Set + Stage 1 Acceptance Contract

Date: 2026-09-10 (Australia/Adelaide)
Status: design-only. No fixture has been created or downloaded. Every fixture is
generated programmatically (never scraped from a real document) or is an
explicitly-licensed sample with provenance recorded in the ledger.

## 1. Fixture rules

1. **No private data.** No real names, signatures, credentials, or private
   documents in fixtures, logs, screenshots, or test output.
2. **Sanitized + self-authored.** Fixtures are generated by a script we write
   (see `scripts/`) so we control content, sizes, and metadata exactly. Any
   third-party sample must go through the dependency ledger with license/etc.
3. **Deterministic.** Each generator takes a seed so regeneration is byte-stable
   (important for hash-based tests and for "source hash unchanged" assertions).
4. **Small by default.** Most fixtures are a few KB; one "large document" stress
   fixture is configurable (e.g. 500–2000 pages) and generated on demand.
5. Fixtures live in `fixtures/generated/` (committed). The generator script
   (`scripts/generate_fixtures`) and its source definitions are the source of
   truth; edit the script, never hand-edit a fixture.

## 3. Stage 1 scope (what this contract covers)

Viewer + page workspace only — see `spec/pdf_editor_ai_handoff_prompt.txt`
Stage 1. Overlays, forms-fill, redaction, signatures, encryption authoring,
OCR, PDF/A-creation are explicitly NOT Stage 1.

Stage 1 feature set:
- open PDF; read+report metadata; render pages & thumbnails
- continuous/single-page view; zoom, fit-page, fit-width, actual-size
- search with match highlighting and next/prev navigation
- text selection + copy from the text layer
- page: reorder (drag), rotate 90/180/270, delete, insert blank, split-out,
  merge-in, extract-select-pages
- metadata edit (title/author/subject/keywords)
- open/save-as with source preservation and atomic publish
- undo/redo for page operations
- themes: XP-inspired (default), dark, blue — all with readable contrast
- accessibility: keyboard shortcuts, focus order, visible errors, status bar

## 4. Stage 1 acceptance tests

### 4.1 Functional (run as automated tests where possible, manual scripted demo otherwise)

A-c1 Open every fixture F-01..F-14. Result is either a valid `Document` or an
     `EngineError` with a structured code. No app crash, no hang.
A-c2 Source-hash invariant: after any non-save operation sequence,
     `document.sourceHash` equals the hash of the originally opened bytes.
A-c3 Save-as round trip: for F-01, F-02, F-03 (and F-06): save to a temp target,
     reopen the saved file, verify: page count equal, page sizes equal,
     rotation-preserving, and `newSha256 != sourceHash`, and the source file on
     disk has NOT changed (byte-compare).
A-c4 Atomicity: force an export failure mid-write (e.g. target dir removed),
     verify old target (if any) and source are untouched and no temp litter
     remains.
A-c5 Overwrite refusal: export attempt whose target == source path is refused
     with `permission_denied`; UI shows a warning, not a silent overwrite.
A-c6 Passwords: open F-04 wrong password → `password_required`; right password →
     opens; permissions flags reported to user.
A-c7 Malformed: open F-08 → `malformed` / `open_failed` structured error; app
     stays usable; reopening a good file afterwards works (no poisoned state).
A-c8 Undo/redo: perform reorder+rotate+delete+insert, undo each step back to the
     original order, redo forward; verify identical page sequences both ways.
A-c9 Search: F-01 term present in text layer → hits highlight, count correct,
     navigation wraps; term absent → "no matches" with no crash.
A-c10 Text selection: F-07 select a multilingual phrase, copy → clipboard matches
      the logical characters (Unicode-aware test).
A-c11 Render fidelity: F-02 renders text+images at zoom 1.0 and 3.0 without blank
      page, tearing, or wrong-color pages (visual sign-off list per platform).
A-c12 Thumbnails: F-03 renders all rotation variants; reorder grid reflects live
      order.
A-c13 Metadata: F-01/02/05 display existing metadata; edit title/author; save-as;
      reopen → edited values persisted, dates sane.
A-c14 Insert blank: insert into F-03 at position 2 (sizes default to first page),
      save-as, reopen — page count correct, blank page renders empty.
A-c15 Split/extract: extract F-01 pages 2-3 → new doc with 2 pages; merge F-01 +
      F-12 → order preserved.

### 4.2 Non-functional budgets (measure & record per platform, do not fabricate)

| Metric | Budget (tool | high bar) |
|---|---|---|
| Cold start to first painted page | < 3 s (any machine), < 1.5 s reference | 
| Idle memory (1 doc open, 10 pages) | < 300 MB (Track A) |
| Large-document open (F-11, 1000 pages) | opens < 10 s, no OOM, scrolling stays responsive |
| Save-as of F-11 | single atomic publish < 5 s after render |
| First build from clean checkout (dev) | documented, reproducible steps |
| Final packaged size (per OS) | recorded; no node_modules shipped |

### 4.3 Platform parity list (fill per OS: Windows / Linux / macOS)

For each of the four themes and every functional test A-c1..A-c15, record:
`[ok | fail | not-applicable]` plus notes. The three platform sheets for the
same version must agree to within stated tolerances; discrepancies become
`PlatformParity` bug entries, not silently accepted differences.

### 4.4 Tooling used to *check* correctness

These are dev/CI tools, not shipped components: `qpdf --check` (if available on
the dev machine only), `python -m pypdf` validations, and our own stream-span
parse checks via lopdf in test code. Static checks (fixture opens, invariants)
do NOT count as live acceptance — see handoff"Rule: static checks are not live
acceptance."

## 5. Definition of done for Stage 1

1. App starts on all three platforms from a portable/standalone artifact.
2. All A-c1..A-c15 pass on that platform's parity sheet; no known crash on any
   fixture open/save path.
3. Non-functional budgets recorded (remotely close to the table above; if out
   of budget, the deviation is documented with cause).
4. Undo/redo, atomic save, and malformed-file resilience proven (A-c2,3,4,7,8).
5. Themes ship default-XP + dark + blue, all pass a contrast spot-check (text on
   buttons/menus readable; measured by a simple WCAG contrast check on the
   theme palette).
6. About → Licenses reflects every D-0x component actually shipped (ledger kept
   in sync).
7. `dev_notes.txt` journal updated per handover rules with results and any
   deviation.
